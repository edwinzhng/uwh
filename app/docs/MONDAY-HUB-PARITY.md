- The new Resources module supports secure links, protected PDF/image and common Office/OpenDocument/CSV/text uploads, document/video filtering, title search, player tags, Club/Staff/Tagged-player audiences, comments, archive/restore and optimistic revision checks. The persisted compatibility value `coaches` is labelled Staff because coaches and admins are included. File bytes are fetched through an authenticated HTTP action; permanent public storage URLs are never returned. Tagged resources include the player's verified guardians and club staff. Cross-club reads and writes are denied server-side. Comments inherit the resource's visibility and show that audience before posting. Creation retries with the same author/key and normalized payload return the saved resource; changed payloads cannot reuse that key. Office/text formats are attachment-only with `nosniff`; executables, active HTML and malformed packages are rejected.

- Video files, thumbnails and voice recordings have purpose-specific validation and authenticated access. Near-limit uploads stream through a server-only storage path; downloads support byte ranges without buffering the entire file in the small HTTP runtime. Categories are Rules, Formations, Drills, Announcements and Other. Program audiences include verified households with an active roster member; changing that roster revokes access without deleting the file. The module does not invent historical recordings or import player data.

- Club → Coaching hours now has a compact seven-day default roster and a separate backup list. Sessions inherit the current weekday until a coach confirms or edits that event. An explicit empty override remains empty; changing a weekly default never rewrites a confirmed event. Backups are suggestions, never automatic assignments. Historical coaching reports count only explicit event assignments and hours, not inferred past weekly schedules.

- Session → Teams retains generation, exclusions, age-group separation and explicit publication, with six formation spots per side and age cohort, an explicit bench, position-grouped lists, accessible move/swap controls and local undo. Draft changes save atomically against the original lineup revision and unpublish the lineup for review. Included attendees must occur exactly once across teams and benches; excluded players cannot be reintroduced. Changes to a benched player's coaching profile invalidate derived teams too.

- The pool board retains an equivalent accessible list/tap workflow. Referee positions do not grant coaching or administrative permissions. Carry-forward reads a published earlier lineup from the same program, keeps only current eligible attendees, and creates a revision-guarded unpublished target. Undo applies to the current unsaved draft; concurrent saved work is never overwritten by an older draft.

- Archival is an admin-only, non-destructive profile action. The directory filters archived profiles on the backend; explicit historical links preserve their identity. Historical attendance remains, future series expectations end, and archived people are excluded from new RSVPs and generated teams. Login permissions are not implicitly revoked. Restore uses the same person ID and leaves ended commitments ended; explicit rejoining works even when archival happened before the original commitment started.

- Session energy is a separate private 1–5 check-in with an optional note of up to 500 characters, not a goal self-rating or coaching skill score. Active eligible players and verified guardians manage their own household entries. Assigned session coaches can read; unassigned coaches and admin-only accounts cannot read another household's notes. Upserts do not duplicate entries under retries. Archival blocks new writes while authorized history/deletion remain available through the service. Cleanup removes both authored entries and entries belonging to erased household profiles.
