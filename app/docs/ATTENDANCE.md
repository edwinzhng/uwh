- Attendance is `(present + late) / all completed eligible sessions`, rounded to a whole percent. Missing responses and unmarked sessions remain in the denominator; no eligible sessions displays a dash. Cancelled events, social events, meetings and future sessions are excluded. A Yes RSVP counts as present until a coach explicitly records present, late or absent, preserving the existing club policy. Recording coverage is shown separately; unmarked is never silently turned into absent.

- Eligibility uses the event’s saved roster when available. Legacy events without a saved roster use the player’s current program membership; historical membership dates cannot be reconstructed from missing data. Combined practices count as one event, with the existing combined-part attendance policy. Attendance reports do not establish physical presence independently of coach records and RSVPs.

- Coaches open **Club → Attendance** to choose a season, month, program and weekday. Search and high/low/declining filters apply to the complete returned roster. Rankings sort the entire roster before progressively rendering 30 rows at a time. A declining trend compares the latest four eligible sessions with the preceding four, or equally sized windows of two or three where less history exists. At least four sessions are required. Club percentages weight eligible player-session opportunities rather than averaging player percentages.

- The dashboard bounds reads to 500 events, 1,000 active players and 10,000 response records. If any bound would produce incomplete statistics, the UI asks for a smaller period instead of presenting partial rankings. Existing results remain visible, labelled as updating, while filter queries run. Completed-session eligibility refreshes with the shared minute clock. The lazily loaded chart reserves its final height.

- In **Practice → Attendance**, a coach can add a private draft or publish player feedback directly from the player row. Feedback retains the practice ID and local date. Published feedback appears on the recipient’s Home with the authoring coach’s name. A submitted author name is ignored; the server records the authenticated coach. Shoutouts remain anonymous and private to their existing recipient/household audience.

- Program roster changes and deactivation control program chat and resource access. Removing someone does not revoke separately targeted player resources. Resources retain their explicit club, program, individual/household or coaches-only audience; uploading large video files is separate work described in [Video storage](VIDEO-STORAGE.md).

- Run `bun scripts/verify-attendance-passwordless.ts` against the isolated local Convex backend, plus `bun run check`. The verification creates and removes fictional accounts and a club, checks the denominator and trends, report access, coach attribution, roster removal/restoration, deactivation, resource audiences, and one-time email links. No existing member or imported role is changed. Browser checks at 320px, 390px and desktop widths and an iOS Metro bundle establish local web layout and compilation, not physical-device behavior.
