- Use `useFormTask.submit(validate, action)`; validate the current values on submission.
- Render one actionable error and prevent overlapping requests synchronously.
- Disable controls that can retarget or interrupt a pending write; do not disable submission merely for invalid input.
- Await backend confirmation before clearing fields, closing or advancing.
- Preserve values and focus on failure; retries of the same payload reuse their operation key.
- Validation errors describe a rejected submission; successful field clearing must not create fresh required-field errors.
- Do not validate from effects watching resets or remount/refocus fields to display errors.
- Use `clear()` for intentional step changes and `run` for auxiliary actions without main-form validation.
- Keep submission side effects inside the task action and use shared friendly-error translation.
- Button `validationError` is for lightweight rejected-click feedback; prefer form tasks for multi-field or multi-step work.
- Mobile-web input text stays at least 16 px in every state; preserve pinch zoom.
- Verify invalid submission, correction, rejection, duplicate clicks, successful clearing and step/context switching.
